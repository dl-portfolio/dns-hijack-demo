# DNS Hijacking Demo

Интерактивная демонстрация атаки DNS Hijacking через публичный WiFi.

**Live demo:** https://dl-portfolio.github.io/dns-hijack-demo/

Независимый демонстрационный проект; не связан ни с какими компаниями или брендами. Кафе («Lunabean Café») и социальная сеть («Friendora», зарезервированный домен `friendora.example`) в анимации вымышлены.

## Описание

Визуальная анимация, объясняющая как хакер может украсть пароли через поддельный WiFi роутер в публичных местах (кафе, аэропорты и т.д.).

**Целевая аудитория:** Нетехнические русскоязычные пользователи (понятно даже 10-летним детям)

## Использование

Откройте [live demo](https://dl-portfolio.github.io/dns-hijack-demo/) или локальный файл `index.html` в браузере и нажмите **▶️ Запустить**.

Все пути к файлам относительные, поэтому корень репозитория можно раздавать как есть (например, через GitHub Pages). Anime.js 3.2.2 загружается с cdnjs с хешем Subresource Integrity (`integrity` и `crossorigin="anonymous"`), поэтому нужен интернет.

## Сценарий атаки

1. Пользователь подключается к WiFi в кафе
2. Открывает браузер и вводит friendora.example
3. DNS запрос отправляется через WiFi роутер
4. Хакерский роутер возвращает ПОДДЕЛЬНЫЙ IP адрес
5. Браузер подключается к поддельному серверу
6. Отображается фальшивая страница Friendora по http:// (браузер пишет «Не защищено», замка нет)
7. Пользователь вводит логин и пароль
8. **УКРАДЕНО!** Пароль отправлен хакеру

## Про замок 🔒 и HTTPS

- У хакера нет настоящего сертификата для сайта, поэтому поддельная страница открывается по обычному `http://`: в адресной строке «⚠️ Не защищено» и нет замка. Если сайт использует HTTPS (особенно с HSTS), браузер покажет предупреждение о сертификате. Не игнорируйте ни то, ни другое.
- Замок означает только, что соединение зашифровано с *каким-то* сайтом, а не что сайт настоящий: мошенник может получить действительный сертификат для своего похожего домена. Проверяйте адрес, а не только замок.
